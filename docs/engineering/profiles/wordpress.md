# wordpress engineering profile
Verify WP/PHP/WooCommerce versions. Capability checks per action and object (current_user_can); nonces for CSRF, never as authorization. REST permission_callback and strict argument validation; AJAX authenticated/unauthenticated hooks only as intended. Sanitize input, validate business rules, escape output late by context; wpdb->prepare for values and allowlist identifiers. Use WP APIs for options, uploads, HTTP (safe remote requests), i18n and settings; protect direct access where appropriate. Prefix/namespaces, hooks, enqueue assets, avoid core edits. WooCommerce CRUD/HPOS compatibility when applicable, order permissions and idempotent payment hooks. Activation/deactivation/uninstall safe behavior and explicit data removal opt-in. WordPress Coding Standards/PHPCS if available; test roles, nonce failures, REST, compatibility. Verify GPL/asset redistribution and marketplace-specific requirements separately.
These are internal engineering controls, not claims of marketplace-specific mandatory framework patterns.
